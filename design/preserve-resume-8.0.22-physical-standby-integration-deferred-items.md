# Preserve/Resume 物理备机集成延期事项

## 1. 目的

本文统一记录当前 Preserve/Resume 项目明确不在本轮实现、而应由后续物理备机产品集成阶段处理的事项。本文不是当前版本的发布门禁，也不表示仓库已经具备真实物理备机、重做日志应用协调器或高可用升主能力。

当前项目只闭环在线接收端的传输、预热和升主就绪准备链路。接收端 `mysqld` 在本次跨节点事务转移期间不支持重启续接；真实升主、单主隔离和生产级物理栅栏提供者由后续项目提供。

## 2. 当前产品边界

- 上线入口以 `DRAIN TRANSACTIONS PRESERVE` 为准；单事务 `PREPARE SHUTDOWN PRESERVE TRANSACTION` 仅用于测试。
- 复制模型为物理复制；不支持逻辑复制、组复制、事务观察者插件或写集合依赖连续性。
- 二进制日志只支持有效的 `ROW` 模式；`STATEMENT/MIXED` 不属于支持矩阵。
- 接收端必须在线完成传输、预热和 `READY` 发布；接收端重启会使当前 epoch 失效并要求重新发起。
- 当前仓库的受保护 THD 挂载只能作为同实例 `TEST_ONLY` 证据，不能声明跨节点事务已经可继续执行业务。

## 3. 后续物理备机项目必须处理

### 3.1 真实物理一致性与 HA 编排

| 来源 | 延期事项 | 后续完成条件 |
| --- | --- | --- |
| `R1-F4` | 非空 `ReadView` 的真实目标端导入 | 在重做日志应用已冻结且物理页面一致的目标上完成导入、冲突处理和回滚证明 |
| `R1-F6` | 严格升主门禁部分成功时的 epoch 原子收敛 | 成功 token 不得永久停留在 `ADOPTED_LOCKED`；对外服务开启前全部进入明确终态 |
| `R11-F1` | 物理升主门禁截止时间的统一时钟域 | 高可用操作截止时间、InnoDB 单调时钟截止时间和取消信号使用同一明确合同 |
| 高可用集成 | 生产级应用状态/物理栅栏提供者 | 外部物理备机产品提供应用 LSN、冻结 LSN、血缘、租约和释放接口 |
| 高可用集成 | 真实角色切换与单主隔离 | 升主门禁只能在目标获得唯一主角色并冻结日志应用/DDL 后执行 |
| 高可用集成 | 生产级受保护 THD 挂载调用方 | 由真实高可用钩子选择目标连接并调用生产挂载核心；不得使用 `TEST_ONLY` 提供者伪造证据 |

### 3.2 会话挂载完整性

这些状态当前不作为本轮发布门禁。后续跨节点挂载若承诺“连接级事务连续性”，必须统一版本化、认证、恢复，并在挂载失败时通过回滚保护器还原目标 THD。

| 来源 | 延期状态 | 当前已知行为 |
| --- | --- | --- |
| `R3-F3` | 默认数据库 / `DATABASE()` | RESUME 后沿用目标连接当前数据库；业务需显式 `USE` 或使用全限定表名 |
| `R13-F1` | `SET TIMESTAMP` / `THD::user_time` | RESUME 后不保证源端时间覆盖状态连续 |
| `R14-F1` | `NO_BACKSLASH_ESCAPES` 经典协议状态位 | 只恢复 `sql_mode` 不等于同步客户端协议状态 |
| `R14-F2` | THD 随机数种子和状态 | RESUME 后 `RAND()` 序列不保证与原连接连续 |
| `R15-F1` | 字符集/时区会话跟踪器 | 目标客户端不保证收到恢复后的会话状态变更记录 |
| `R16-F2` | `lc_time_names` | 本地化日期表达式沿用目标连接的语言区域设置 |

后续实现必须覆盖 SQL RESUME、升主挂载和失败回滚三条路径，不能只修改元数据编解码器。

### 3.3 临时表附属文件大对象资源治理

`R13-F2` 延期到物理备机集成阶段：临时表附属文件的读取、校验和物化必须改成有界分块流程，接入 `TEMP_SIDECAR_READ_BUFFER` 资源租约，并证明多 token 并发时不会突破单 token/全局内存预算。

在该项完成前，不承诺大临时表附属文件的有界内存 RESUME。当前测试和发布证据必须报告附属文件大小上限，不能把小对象通过等同于大对象资源安全。

## 4. 条件性事项

`R1-F7` 的持久化严格意图启动收敛，仅在后续产品决定支持接收端/升主过程中 `mysqld` 重启时才进入实现范围。当前仅在线合同下，接收端重启直接使 epoch 失效，不要求从持久接收日志或意图记录重建严格注册表。

如果未来打开重启续接，必须同时设计：意图重放、严格注册表重建、本地恢复排除、暂存工件保留、epoch 隔离和运维可见终态；不得只增加一个启动重放辅助函数。

## 5. 明确不纳入后续物理备机项目

- `R1-F1`、`R13-F3`：单事务 PRESERVE 的 token 协议和容量治理；该入口不上线。
- `R4-F1`：写集合/并行复制依赖连续性。
- `R16-F1`：复制插件强制回滚/外部分配 GTID 上下文。
- `R5-F5`：组复制或第三方事务观察者的暂停/接管生命周期。
- 接收端重启续接，除非未来产品显式改变第 4 节的决策。
- 真实逻辑副本、`WRITESET/WRITESET_SESSION`、`STATEMENT/MIXED` 二进制日志连续性。

这些排除项不得重新包装成当前 Preserve/Resume 的发布阻塞项；若产品范围变化，必须先更新本文和支持矩阵，再制定独立设计。

## 6. 后续项目进入条件

后续物理备机项目开始实现前，至少需要具备：

1. 可注册的生产级重做日志应用/物理栅栏提供者。
2. 可冻结日志应用、DDL 和页面布局的不可撤销租约。
3. 真实源节点/备节点数据模型及单主角色切换。
4. 生产级受保护 THD 所有权、KILL/断连隔离和挂载调用方。
5. 分级证据标签：`IN_REPO`、`SIMULATOR`、`HA_BLOCKED`、`PRODUCTION_REDO_APPLY`。
6. 发布级端到端测试能够证明物理一致性、门禁/挂载成功和续作后的提交/回滚，而不是用同实例或 drain 前拷贝代替。

## 7. 维护规则

- 当前审核中被延期的事项统一引用本文，不在多个计划中重复定义不同合同。
- 新增延期项必须写明当前行为、风险边界、未来触发条件和验收证据。
- 当前项目若修改这些状态，只能做失败关闭或支持矩阵收敛，不能在缺少物理备机环境时宣称已完成跨节点语义。
