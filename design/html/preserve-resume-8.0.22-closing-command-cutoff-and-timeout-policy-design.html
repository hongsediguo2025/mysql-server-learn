WARMCOPY_CLOSING 全命令截断与超时事务降级设计

Phase1 尽量吸收正在执行的长命令；CLOSING 发布后，普通业务连接的所有新 command 立即返回 4020； 专用 HA 管控连接保持可用； 已在执行的命令按统一 deadline 收敛。超时后由一个布尔策略决定整批终止，或只排除超时事务并继续 transfer。

1. 设计结论

一句话裁定 WARMCOPY_CLOSING 是普通客户端业务 command 的硬截断点，不再是“风险 SQL 分类点”。 Phase1 尾部只做轻量 readiness 观察，用来减少进入 CLOSING 时已经在执行的长命令； 观察不承担正确性，CLOSING 门禁和统一 monotonic deadline 才承担正确性。

进入 CLOSING 之前

正常业务继续执行，Phase1 继续构建和发送可提前完成的 Preserve 内容。

在 Phase1 尾部只读统计正在执行的 command 数量与最老执行时长。若已有明显长命令，则在 Phase1 剩余预算内等待其自然完成。

进入 CLOSING 之后

普通业务连接的所有新 command 在 dispatch 入口直接返回 ER_PRESERVE_TRX_SESSION_DRAINED，错误码 4020；专用 HA 管控连接整体豁免。

切换前已经执行中的 command 继续完成；到参数 B 的绝对 deadline 仍未完成时，由参数 A 决定整批失败还是只排除对应 token。

不要扩大“部分成功”语义 参数 A 只处理“CLOSING 时旧 command 未按期结束”这一种情况。snapshot、seal、传输、digest、receiver commit、 final metadata 或任一 survivor 的 Preserve 失败，仍按现有 all-or-nothing 语义终止整批。
A=OFF 当前不是生产物理升主能力 当前仓库没有 source terminal authority fence 与 production physical apply provider。A=OFF 可以实现和验证 subset transfer， 但在这些 provider 落地前只能用于 standalone/simulator 证据，不得作为在线物理升主的生产开关；默认 A=ON 保持现有整批失败语义。

2. 背景与场景

本设计服务于在线 transfer 和未来物理备机计划内升主，不服务于本地 shutdown/startup 场景。

2.2 为什么必须由 mysqld 返回 4020

HA 可以通知代理停止新建连接，但已有代理连接在没有收到特殊错误前仍会继续下发 command。 因此，只有 mysqld 在 CLOSING 入口对每个新业务 command 返回 4020，代理才能确定该 command 未执行、可以安全挂起。

command 结果必须闭合 DRAIN 完成时，CLOSING 之前已经接收的 command 要么已经正常完成，要么已经被明确判定为超时； CLOSING 之后接收的业务 command 均已返回 4020。代理侧不存在“已经发给 mysqld 但不知道是否执行”的悬空 command。

2.3 HA 专用管控连接

协议层在解析 SQL 之前已经能够读取认证后的 Security_context。首版直接以 Security_context::priv_user() 精确等于 preserve_trx_ha_admin 识别专用 HA 账号， 并要求该账号持有原有的 SHUTDOWN_ACL。gate 只读取认证账号与有效权限，不解析 SQL 文本、 不按业务命令类型做白名单，也不新增 role、动态权限或 wire capability。

  • HA 身份必须同时满足：认证上下文中的 priv_user() 精确等于 preserve_trx_ha_admin，且有效全局权限包含 SHUTDOWN_ACL。
  • root、SUPER、SYSTEM_USER、SHUTDOWN 或其他动态权限都不会单独获得 HA 身份；MySQL 初始化 root 自动拥有大量权限，因此不能把任一普通 privilege 等同于该专用账号属性。
  • protocol gate 与 SQL gate 仅按上述身份放行，不读取 SQL 文本，也不根据连接当前要执行的是 RESET、SHOW 或 DML 做分类。
  • RESET DRAIN 真正执行时再次要求固定 HA 账号，并沿用 check_global_access(..., SHUTDOWN_ACL) 做最终授权。
  • HA 管控连接必须保持 autocommit 且无活动业务事务。readiness 忽略该控制连接；target 枚举若发现它持有显式事务或 RW participant，则整批 fail closed，不把该事务静默排除。
信任边界 该连接在 CLOSING 中执行 DML 会绕过 4020，破坏业务封口假设。因此它必须是 HA 专用控制面连接； 内核不为“高权限账号同时承载业务 SQL”提供 Preserve 正确性保证。

首版只在 protocol gate 的唯一计数点累计 Preserve_trx_closing_control_connection_commands，用于发现 CLOSING 期间控制连接的实际使用；SQL gate 不重复计数。本文不新增逐 DML warning 或另一套 SQL 风险分类，具体语句继续由现有 audit/general log 记录。该指标只帮助发现账号误配，不能把“控制账号承载业务 SQL”变成受支持用法。

3. 边界与非目标

本轮设计范围

  • Phase1 尾部 lightweight readiness 观察。
  • CLOSING 后普通客户端的所有新业务 command 返回 4020。
  • 基于认证上下文中的固定 preserve_trx_ha_admin 用户名与 SHUTDOWN_ACL 识别并豁免 HA 专用管控连接。
  • 参数 B 定义旧 command 的统一 deadline。
  • 参数 A 定义整批失败或单 token 排除。
  • 复用现有 per-token ABORT。
  • source 进入 CLOSING 后只按 HA 管控连接身份豁免，不为其他命令类型增加放行口。
  • survivor set、excluded set 与 HA 结果合同。
  • 并发裁决、指标和真实测试。

明确不做

  • 不实现物理复制 apply/fence provider。
  • 不实现 peerid 的 Tx 到 Ty attach。
  • 不修改本地 shutdown/startup Preserve。
  • 不 KILL 长 SQL，不强制回滚事务。
  • 不新增 transfer wire frame 或 wire version。
  • 不改 artifact 格式或内核对象序列化。
  • 不新增调度线程、预测器或 Pre-CLOSING 状态。
  • 不支持任意 Preserve 失败后的部分成功。
  • 不新增专用账号表、动态权限或控制面 wire 协议。

零新 InnoDB hook 零新 receiver crash replay 零新 wire 协议 零通用 SQL 黑名单

5. 当前缺口

命令漏口

普通 SELECT、DO、部分 SET、协议级命令可能在 CLOSING 后继续执行。即使它们看似只读，也可能建立 ReadView、改变会话上下文，或通过 stored routine 触发写入。

长命令放大 Phase2

当前在 Phase1 末尾直接进入 CLOSING。若此时已有明显长 SQL，Phase2 首段只能被动等待，容易消耗全部 close budget。

超时粒度固定

一个 target 未到达 quiesce boundary 会终止整批。计划内倒换需要可配置地排除该事务，让其余事务继续 Preserve。

不能继续扩 SQL 黑名单 目标不是继续判断哪条 SQL “危险”，而是在 CLOSING 后建立清晰的命令所有权边界： transition 之前已经开始执行的 command 归 source 完成；transition 之后的新业务 command 一律不执行并返回 4020。

7. Phase1 尾部 lightweight readiness

readiness 的目的只是减少 CLOSING 刚发布时的在执行命令数量，尤其是避免把已经明显变成长 SQL 的 command 带入 1 秒 closing deadline。

7.1 观察内容

在最后一次 Phase1 target/lock/binlog prepare 完成后、发布 CLOSING 之前，执行只读 THD 观察：

  • inflight_business_command_count：当前正在执行的业务 command 数。
  • oldest_inflight_command_age_ms：最老 command 的已执行时长。
  • long_command_count：执行时长已经达到参数 B 的 command 数。

不读取 THD::start_utime。在现有 preserved_trx_mark_inflight_command_packet() Preserve hook 中， 为可执行长业务工作的 command 记录受同一同步纪律保护的 preserve_command_sequence 与 preserve_command_started_monotonic_us。readiness 仅用它们识别和统计当前 command；不修改通用 THD::set_time()，也不把该 identity 带入 artifact 或 wire。无活动事务的 HA 管控连接不计入这些指标。

OFF-path 合同 preserve_trx_enable=OFF 时，command marker 必须在写入上述字段、读取 monotonic clock 或获取 LOCK_thd_data 之前立即返回。这里保证的是“无新增字段写入、取时钟和取锁”，不宣称消除现有 hook 调用与一次 enable 分支本身的 CPU 开销。

7.2 进入 CLOSING 的判断

观测结果动作理由
没有执行时长达到 B 的 command立即发布 CLOSING。不等待 command 数清零，避免高 QPS 下 Phase1 永不结束。
首次采样存在执行时长达到 B 的 command冻结本次等待集合，继续停留在 Phase1，直到集合中的原 command 全部完成或 Phase1 deadline 到达。业务尚未被截断，让已经很长的 command 尽量在宽松阶段完成，同时避免持续流量无限扩充等待集合。
Phase1 deadline 到达停止 readiness 等待，立即进入 CLOSING。readiness 不得把 drain 变成无界等待。
RESET、owner KILL 或 Phase1 participant 失败沿用现有退出/回撤路径。不创建新的失败语义。

7.3 预算与采样纪律

  • 不新增 readiness sysvar。长命令阈值复用参数 B。
  • 等待集合只在 readiness 首次采样时冻结；元素身份使用 (thread_id, preserve_command_sequence)。同一 THD 开始下一条 command 即表示原 command 已完成，新 command 交给 CLOSING+B 处理。
  • readiness 等待上限复用现有 Phase1 总预算。实现时在 two-phase drain 开始处捕获一个 monotonic absolute deadline。
  • 当前 preserve_trx_transfer_phase1_timeout_ms 主要用于 transfer operation timeout；实现应明确同一数值也限制 Phase1 readiness，不能只依赖单次 socket timeout。
  • 采样 sleep 必须发生在不持 LOCK_thd_data、manager mutex、participant lock 或 transfer session mutex 的位置。
  • 首次采样执行一次全 THD 摘要扫描；后续只按冻结的 thread id 定点查询，不得每 10ms 反复全量扫描所有 THD。
  • 定点查询不读取事务 payload、不扫描 Undo、不导出锁对象；固定 10 至 50ms 采样即可，不做自适应算法或新 worker。
为什么不能等待 inflight count 变为 0 Phase1 期间代理仍可在已有连接上持续下发 command。在高吞吐下，count 可能始终非零。 readiness 只等待首次采样时“已经明显长”的 command；随后必须依靠 CLOSING 截断新 command，关闭最后的竞态窗口。

8. CLOSING 全命令截断

8.1 “所有 command”的精确定义

本文门禁只作用于 client protocol dispatch，不扩展到 replica applier、event scheduler 或其他 internal THD。 对普通客户端连接，所有新业务 command，包括文本 SQL、prepared statement 执行、cursor fetch、schema/session 操作以及其他 classic protocol 业务命令， 均必须在产生业务副作用前返回 4020。不能只覆盖 COM_QUERY，也不能继续依赖 CF_CHANGES_DATA。

实现规则是 default-deny 普通认证客户端在 CLOSING 中默认被截断；只有 HA 管控连接可以继续执行新命令。DRAIN owner 的当前 DRAIN 与 t0 前 command 属于已经进入执行的旧 command；无响应清理包只完成协议资源释放，不构成业务命令放行。 COM_CHANGE_USER、COM_RESET_CONNECTION、COM_STMT_RESET、PING、STATUS、KILL 等均不得因当前风险分类没有命中而漏过。

8.3 错误映射

建议新增一个内部 block result，例如 BLOCK_CLOSING_DRAINED，由 protocol 和 SQL 两个 dispatch 入口都映射为 ER_PRESERVE_TRX_SESSION_DRAINED。不要把全局 CLOSING 伪装成 THD 已永久进入 PRESERVED_DRAINED， 因为 RESET 后这些连接需要恢复正常执行。

两个 gate 共用 preserve_trx_is_ha_control_connection(thd)：直接检查 Security_context::priv_user() 是否精确等于 preserve_trx_ha_admin，并确认有效权限含 SHUTDOWN_ACL。该判断发生在 SQL 解析前，不读取 SQL 文本。实际 RESET 执行仍再次检查账号与 check_global_access()；普通 root、PROCESS、SUPER、SYSTEM_USER 或用户名包含 admin 都不会自动获得豁免。 连接误持事务不是 gate 的 SQL 分类条件，而是在 target 枚举中触发整批 fail closed。

4020 的唯一承诺 本次 command 没有执行，代理可以挂起。4020 不承诺该事务最终一定被 transfer、prewarm 或 promotion； 后续 HA 还要结合 DRAIN result 的 survivor/excluded 列表决定重放位置。

保持错误码 4020 不变，但同步把客户端文案改为中性表述，例如： Preserve drain is active; this command was not executed。该文案同时兼容 CLOSING 截断与已 drained 会话，不能继续声称事务已经 Preserve 成功。

诊断窗口 普通业务连接在 CLOSING 中执行 SHOW、STATUS、KILL 仍返回 4020，不增加命令级诊断白名单。 HA 使用专用管控连接查询状态或执行 RESET，因此既保留业务硬截断，也不存在控制面诊断盲窗。

9. 参数 B：CLOSING command deadline

参数名
preserve_trx_drain_closing_command_timeout_ms
建议默认值
1000 ms。该默认值需在实现评审时由真实长 SQL/高并发测试确认。
时间起点
manager state 成功发布 WARMCOPY_CLOSING 的 monotonic 时点 t0。
计算公式
closing_command_deadline_us = min(t0 + B * 1000, overall_close_deadline_us)

9.1 这是全局 deadline，不是每事务 timeout

  • 所有 t0 前正在执行的 command 共享同一个 deadline。
  • 不能在等待某个 token 时重新开始 B，否则 N 个 target 会串行放大为 N×B。
  • target wait 应批量观察或逐个读取同一绝对 deadline。
  • deadline 判断使用 monotonic clock，不使用 THD 的启发式 command start 时间。

9.2 两级 deadline 与串行预算

参数 B 只度量“旧 command 收敛窗口”，它是现有 CLOSING 总预算内的子截止线，不是独立于总预算之外再追加 1 秒。 有 warmcopy participant 时，现有 preserve_trx_warmcopy_close_timeout_ms 从 t0 形成 overall_close_deadline_us；没有 warmcopy participant 时，复用现有 drain hard deadline 作为外层安全上限。

阶段预算合同禁止行为
旧 command 收敛所有 target 共用 min(t0+B, overall_close_deadline)。不得按 token 重启 B。
participant prepare/close只使用同一个 overall_close_deadline 的剩余时间。command 裁决后不得重新获得完整 30 秒。
survivor tail / seal / COMMITpreserve_trx_transfer_phase2_timeout_ms 继续约束 classic session 的 connect/read/write 单次操作。不得把默认 3 秒解释成整个 tail 的绝对总时限。
CLOSING 到 FINAL_ACK以真实端到端指标计量，并受既有 drain/participant 失败边界约束。不得用 B+3s 或其他参数相加伪造 SLO。

当前执行顺序保持不变：先让旧 command 到达边界并冻结 survivor/excluded，再关闭 participant、补齐增量对象并发送最终 epoch。 不能为了并行缩短时间而在旧 command 尚可继续修改 binlog cache、锁或会话状态时提前关闭 participant。

若 B 大于外层剩余预算，运行时继续按 min() 安全收敛，不增加跨 sysvar 的硬性 SET 校验。 实现应累计 closing_deadline_clamped 并记录有效 command budget；若 command wait 消耗完外层预算，按稳定原因码失败，不能静默给 participant 重新分配时间。

禁止预算偷换 不能把 3 秒 operation timeout 写成 Phase2 总预算，也不能让 participant prepare/close 在 command wait 后重新开始一轮 30 秒。 现有 Phase2 总指标可继续覆盖 CLOSING 后全链路，但报告必须另外给出 command wait、participant close、transfer tail 和 CLOSING 到 FINAL_ACK 总时间。

实施时同步修正 sysvar help：preserve_trx_transfer_phase1_timeout_ms 同时作为 Phase1 transfer operation timeout 的数值来源与 本设计 readiness 的绝对外层预算；preserve_trx_transfer_phase2_timeout_ms 是 classic session 单次 connect/read/write operation timeout， 不得继续描述为 Phase2 “maximum total milliseconds”。

10. 参数 A：整批失败或排除超时 token

参数名
preserve_trx_drain_command_timeout_fail_batch
建议默认值
ON，保持现有 all-or-nothing 行为兼容。OFF 本轮只开放给内部测试/standalone simulator；生产物理升主必须等待 source terminal fence 与 apply provider 落地。

10.1 A=ON：整批终止

  1. 任一 target 在 closing_command_deadline 仍为 PENDING_QUIESCE，本次 drain 失败。
  2. 终止 source transfer epoch，receiver 不得形成 accepted epoch。
  3. 清除 batch generation，沿用现有回撤/失败路径。
  4. 不 KILL 仍在执行的 command，不把 timeout 转换成事务 rollback。
  5. HA 让原主继续承担业务；代理在 HA 确认后把已挂起的 4020 command 重放到原连接。

10.2 A=OFF：只排除未按期结束的 command 对应事务

  1. deadline 到达后，在目标 THD 的同一次 LOCK_thd_data 临界区校验本 generation 与 PENDING_QUIESCE。
  2. 若仍超时，在该临界区内原子完成“分类为 excluded → state=NONE → generation=0 → 关闭 temp capture epoch”；禁止先分类、解锁后再清 state。
  3. 释放 LOCK_thd_data 后，再把 source connection id 加入 epoch-local excluded_tokens 并执行可能阻塞的 transfer 操作；锁内不得发网络包或取得 participant lock。
  4. 若 token 已向 receiver DECLARE 或发送 Phase1 object，复用现有 abort_phase1_transfer_targets_not_quiesced() 接缝，调用 abort_token(token, "closing_command_timeout")。
  5. ABORT 必须成功且 ACK 明确；失败或 ACK 不明确时立即整批失败，不得继续构造 survivor epoch，也不得发送 COMMIT_EPOCH。
  6. 所有 excluded token 都得到确定 ABORT 后才冻结 survivor set；后续 Preserve、seal、final fact 与 COMMIT 只处理 survivor。
  7. DRAIN result 返回 excluded token 及稳定原因码，供 HA 通过 peerid 识别不可续作事务。

receiver 侧现有 ABORT handler 会清 strict state、prepared token 与 staging；清理失败转入现有 cleanup-pending，并保持该 token 不可 promotion。 source participant 的 Phase1 临时状态不新增逐 token 清理接口。binlog/lock warmcopy 均按 source thread id 保存候选，最终 prepare/close 只接收 survivor/quiesced target；excluded token 不进入任何 survivor final artifact。遗留的 source 进程内 working state 在整 epoch abort/reset 或 success finalize 时统一释放。当前成功路径随后 shutdown，可继续调用 finalize_participants_for_shutdown()；未来 source 不退出的在线 HA wrapper 必须调用现有 finalize_participants() 完成普通成功清理。

artifact 隔离不变量 excluded token 在排除时点之后产生的 binlog cache、lock 或 temp-table 变化，不得进入任何 survivor 的 digest、fingerprint、final metadata 或 epoch fact。 正确性依靠原子清 generation/capture、per-target participant 容器与 survivor-only finalization；不要求为此增加逐 token participant cleanup API。

12. HA 与代理合同

12.1 DRAIN 返回结果

内核向 HA 同步返回结构化结果，不要求代理解析 error log、SHOW STATUS 或 shutdown 日志：

drain_result {
  generation
  outcome: SUCCESS | SUCCESS_WITH_EXCLUSIONS |
           NO_PRESERVABLE_TOKENS | FAILED
  survivor_tokens[]
  excluded_tokens[] {
    source_connection_id
    reason = CLOSING_COMMAND_TIMEOUT
  }
  closing_started_us
  closing_deadline_us
}

内部 HA 调用面直接返回上述结构；SQL DRAIN TRANSACTIONS PRESERVE 使用一个结果集承载同一内容。 结果集按 token 一行，包含 generation、outcome、source_connection_id、 token_role（SURVIVOR/EXCLUDED）、reason 和两个 closing 时间字段；没有 token 时返回一行 summary，token 字段为 NULL。

协议兼容与升级 现有 SQL DRAIN 成功面是 OK packet；改为结果集属于调用协议变更。HA/代理必须先升级为完整读取结果集、解析 survivor/excluded， 并容忍结果发送完成后连接因 source shutdown 断开，再部署返回结果集的 mysqld。首版采用 HA 与 mysqld 协同升级，不增加旧 OK/新结果集双模式、协商参数或 wire 版本。
响应必须先于 server shutdown SQL 路径只能发送一个完整 response：FINAL_ACK 后先把 active attempt 原子推进到不可 RESET 的 terminal handoff， 再写完并 flush 上述结果集，最后进入 SHUTDOWN_REQUESTED 和 server shutdown。 最小实现是在现有 shutdown() 增加窄范围的 send_response 参数，默认值保持 true；普通 SHUTDOWN 调用不变， 只有已经完整发送 DRAIN result 的 Preserve 路径传 false，从而只跳过 my_ok() 而继续执行原权限、日志和 kill_mysql() 流程。 若 result 写入或 flush 失败，receiver 已接受的 epoch不能反向撤销；source 仍进入 terminal handoff，HA 按控制连接响应丢失处理。 error log/status var 只用于诊断，不是 HA 的结果传输面。

12.3 FINAL_ACK 后边界不变

source 收到 FINAL_ACK 后 transfer 协议结束。target 后续 prewarm、TTL、promotion 或 abandon 由 target 和 HA 管控； source 不查询 READY、不触发 promotion，也不因 target 后续失败重新打开本 epoch。

14. 并发与竞态

14.1 transition 与新 command

command admission 必须读取 manager state 的同一发布序列。若 command 在 CLOSING publication 前完成 admission，它属于旧 command； publication 后才进入 gate，普通业务连接返回 4020，HA 专用管控连接绕过门禁。不能出现“看见 CLOSING 但仍按 SQL 风险分类放行”的中间态。

classic protocol 每个连接一次只处理一个 command；t0 前旧 command 未完成时，同连接不会并行 dispatch 下一条 command。 本设计依赖该半双工不变量区分 old/new command；未来若引入同连接 pipelining，必须重新设计 command identity 与 admission，而不能沿用本合同。

控制连接豁免只解决控制面可达性。readiness 直接忽略专用控制连接，避免 PING/SHOW/RESET 拖住 Phase1；target 枚举若发现它持有显式事务或 RW participant，则必须把该事实作为不满足控制连接合同处理并整批失败， 不能一边绕过 command gate 一边把它从 Preserve 正确性集合中静默删除。

14.2 command boundary 与 deadline 同时发生

在目标 THD 的同一次 LOCK_thd_data 临界区完成一次性裁决：

  • 若 command boundary 已发布 QUIESCED 或 DRAINED_NO_TRANSACTION，按完成处理。
  • 若仍为本 generation 的 PENDING_QUIESCE，A=ON 按整批失败；A=OFF 在锁内原子分类并清 state/generation/capture。
  • 排除后即使 command 下一微秒完成，也不能重新加入已冻结的 survivor set。
  • excluded vector、ABORT 网络发送和 participant 操作在解锁后完成；持 manager mutex/participant lock 时不得获取目标 LOCK_thd_data。

14.3 RESET

RESET 赢时沿用现有 attempt/generation 回撤：立即解除 CLOSING gate，让原连接恢复业务；readiness waiter、target waiter 与 sender 看见 reset marker 后退出。 本设计不重新定义 FINAL_ACK 后 RESET 的所有权合同。

14.4 ABORT 与 COMMIT

所有 timeout exclusion 必须在 source epoch session 进入 commit 前完成。现有 abort_token_locked() 已拒绝 m_epoch_committed 或 m_commit_in_progress，应继续作为硬约束。每个已声明的 excluded token 必须得到确定 ABORT ACK； 任一失败或 ACK ambiguity 都终止整批，不能先从 final fact 删除 token 再继续 COMMIT。receiver 的物理 staging cleanup 复用现有 handler，失败只形成 cleanup debt， 不会把 token 恢复为 promotion-visible。

14.5 DRAIN result 与 shutdown

survivor/excluded 集合在 COMMIT 前冻结；FINAL_ACK 确认后结果内容不再变化。active attempt 必须先 CAS 到 terminal handoff，拒绝后续 RESET， SQL owner 再在进入 SHUTDOWN_REQUESTED 和 server shutdown 前同步发送结果，且 shutdown 路径不得再发送第二个 OK。 若连接在响应期间断开，不能反向修改 receiver 已接受的 epoch；HA 按控制连接断开处理，不由 source 重开 transfer。

17. 测试计划

验收主线：MTR + Standalone E2E 测试代码和 release 证据以真实 mysqld 为主。MTR 负责单/多连接协议行为、权限、DEBUG_SYNC 竞态和零副作用； standalone 双 mysqld E2E 负责 source/receiver、ABORT/COMMIT/FINAL_ACK、READY 与 token 对账。 GUnit 只验证不需要网络、THD 生命周期或真实 receiver 的纯决策逻辑，不能单独关闭任何端到端验收项。

17.1 GUnit：仅纯决策辅助

  • default-deny command 分类表及 t0 前 inflight、HA 管控连接、无响应 teardown 的纯 block-result 决策。
  • min(t0+B, overall close deadline)、剩余预算、clamp 计数和多 target 不产生 N×B 的纯时间计算。
  • readiness frozen identity 集合的 sequence 比较、首次冻结和后续新 command 不扩充集合。
  • A=ON/A=OFF 的纯分类结果、全部 excluded 判定以及 DRAIN result 序列化。
  • 不得为方便 GUnit 在生产头文件增加 *_for_unit_test API；需要真实 THD/网络/receiver 的行为直接进入 MTR/E2E。

17.2 MTR：协议、并发与零副作用主回归

  • 在 CLOSING DEBUG_SYNC 窗口由普通连接发送 COM_QUERY、prepared execute/fetch、INIT_DB、PING、SET、DO、SHOW、STATUS、KILL、CHANGE_USER、RESET_CONNECTION、STMT_RESET 等，除明确的无响应 teardown 外均得到 4020。
  • 认证用户名精确为 preserve_trx_ha_admin 且有效持有 SHUTDOWN_ACL 的专用连接，在同一窗口可执行 PING、SHOW STATUS 和 RESET DRAIN；普通 root 或仅持 SHUTDOWN 的连接不能绕过。
  • 控制连接依次执行 PING、SHOW STATUS 和 RESET DRAIN 时，Preserve_trx_closing_control_connection_commands 每个 protocol command 只增加一次，SQL 二次门禁不得重复计数。
  • 仅持有 PRESERVE_TRX_TRANSFER_ADMIN、不具备 HA 身份的连接在 source CLOSING 窗口同样得到 4020；另设 receiver 正常状态用例证明原 transfer handler 未受影响。
  • 另一个 HA 控制连接持有活动事务时，DRAIN 整批失败而不是忽略该事务。
  • 验证每条被 4020 截断的 command 没有数据、事务、schema、session variable 或 cursor side effect。
  • 4020 客户端文案只声明 command 未执行；CLOSING 下无事务会话和随后被 excluded 的事务均不得收到“事务已经 Preserve”的误导文本。
  • 一个 t0 前已执行的长 command 正常返回；同连接下一条 command 得到 4020。
  • A=ON：确定性长 command 超过 B，source 不发送 accepted epoch；HA 解除 gate 后，代理在原连接重放先前 4020 command 成功。
  • A=OFF 下构造 unsupported/unstable target，断言仍整批失败，不被归类为 timeout exclusion。
  • DRAIN result 返回被排除的 source connection id 和 CLOSING_COMMAND_TIMEOUT。
  • SQL 客户端在 source shutdown 前完整收到唯一 DRAIN result set，不再收到额外 OK packet。
  • 全部 token 超时返回 no-preservable，不发送空 COMMIT；no-target/no-quiesced 分支也走同一结构化结果面。
  • RESET 在 readiness/CLOSING wait 中解除 gate；代理模拟客户端在原连接重放 4020 command 成功。

17.3 Standalone 双 mysqld E2E：transfer 真实性主证据

  • source 真实 DRAIN，target 真实 receiver save/prewarm；代理模拟层挂起 4020 command。
  • 内部测试能力开启 A=OFF 时，survivor epoch 正常 FINAL_ACK，excluded token 不出现在 target READY summary。
  • 3 个 token 中 1 个超时：receiver epoch fact 只有 2 个 survivor，第三个为 ABORTED 且不可 READY。
  • excluded 旧 command 在排除后继续产生真实写入，receiver 侧 survivor digest/fingerprint/final fact 均不含该 token 的变化。
  • 在真实 frame/ACK 路径注入 ABORT failure 和 ACK ambiguity，断言 source 整批失败且 receiver 不接受 COMMIT_EPOCH。
  • 全部 excluded、no-target 和 no-quiesced 分支分别验证无空 epoch、唯一结构化结果及 receiver 状态收敛。
  • readiness 场景分别覆盖无长 SQL、一个长 SQL在 Phase1 完成、长 SQL跨越 Phase1 deadline。
  • 报告 readiness、command wait、participant prepare/close、transfer tail、CLOSING 到 FINAL_ACK 时延和 source/receiver token 对账。
证据边界 当前仓库没有真实物理复制和升主流程。E2E 只能证明 command 截断、subset transfer、receiver save/prewarm 和 simulator 合同， 不能宣称完成真实物理 promotion E2E，也不能据此把 A=OFF 标记为 production-ready。

17.4 Local startup E2E：停机窗口与续作顺序模拟

  • 真实 DRAIN 关闭 mysqld，并通过 socket、pid file 和 quiet period 确认旧进程已经退出。
  • 确认停机后，在旧业务连接上发送一条尚未执行的 SQL，必须观察到 transport disconnect；在此之前不得启动新 mysqld。
  • 启动 mysqld并完成 startup recovery 后，先对对应 token 执行真实 SQL RESUME；RESUME 未成功时，原 SQL 的发送次数必须为零。
  • RESUME 成功后在新连接上重放同一 SQL，发送次数严格为一；报告记录 SQL digest、disconnect、restart、RESUME、replay send/completion 的单调时间序列。
  • 该用例只验证共享 startup/resume 内核与代理时序，可为未来 promotion 对接提供证据；它不冒充物理备机升主 E2E。

17.5 隔离性回归

  • preserve_trx_enable=OFF 时 command dispatch 与原生 MySQL 完全一致。
  • MTR 运行同一 command matrix 验证 OFF 时原生行为；辅助 source-shape lint 同时锁定 OFF 短路位于新 CLOSING default-deny 分支以及 command identity 字段写入、monotonic clock 读取和 LOCK_thd_data 获取之前。
  • 单事务 local preserve、shutdown/startup recovery、SQL RESUME 行为不变。
  • A/B 只在 two-phase online transfer CLOSING 中生效。
  • 既有 receiver restart 无状态、FINAL_ACK 后 source 解耦合同不变。

18. 推荐落地顺序

  1. S0：锁定测试合同。先补失败态 MTR 和最小 GUnit：用真实 command 证明当前 COM_QUERY 会漏过、BLOCK_DRAINING 错误码不对、timeout 只能整批失败，并锁定 HA 控制连接身份合同。
  2. S1：全 command 4020。只改 manager gate、sql_parse 映射和 4020 文案，落实 default-deny；只有 t0 前 inflight 和 HA 控制连接可继续，无响应 teardown 只释放协议资源。
  3. S2：参数 B。把 command deadline 嵌入现有 overall close deadline，传递剩余预算，并分离 command wait、participant close 与 transfer tail 指标。
  4. S3：Phase1 readiness。复用现有 command marker 维护同步 identity；增加栈内 observer，首次扫描冻结 offender，后续定点查询，复用 B 阈值和 Phase1 budget，不增加线程。
  5. S4：A=OFF + HA result 单一交付切片。在同一不可拆分切片中完成原子排除、survivor/excluded set、确定 ABORT、结构化结果、唯一 response 与双 mysqld E2E；完成前 A=OFF 不能对外启用。
  6. S5：未来 production provider。由物理备机项目接入 source terminal fence、target apply catchup 和 HA authority 后，才评审 A=OFF 的生产启用。

S1、S2、S3 可先以 A=ON 保持现有整批语义。S4 的内部实现可以分小提交，但 subset epoch 与 HA 可观测结果必须作为同一 release unit， 不能留下“receiver 已接受 survivor、HA 却不知道谁被排除”的中间能力。
