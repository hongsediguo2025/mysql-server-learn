# sysbench读写500并发：两轮运行记录

> **2026-10-04 版本说明：历史版本记录。** 文内“当前/尚未完成/通过”和源码路径均属于记录时点；旧 PS 定义/参数/重建方案不再适用，原失败与测量不改写为新版本成绩。 现行职责见[详细设计](detailed-design.md)和[PS 删除与 cursor 关联](ps-transfer-removal-and-cursor-attach.md)，最新状态见[任务跟踪 E63/E64](task-tracker.md)。下文保留历史事实，不作为现行实施清单。

按用户要求，将原full读写模型改为500并发，独立运行2轮。
**两轮均完成交接，500个survivor token全部READY；strict Phase2均小于2秒，
但末命令到Final ACK均超过500毫秒，两轮原性能验收均失败。**

## 工作负载与验收口径

Release SHA256：`f4b7082a4ae6a7ea08cce8033624d32b1361a12f14706e65f3acbb87d97b7d43`。
使用当前`ha_preserve_trx`未提交实现；沿用原native runner和原读写Lua。
相对此前1000并发的full读写模型，仅修改并发1000→500、重复5→2。

- `oltp_read_write`、显式事务、实效REPEATABLE-READ；128表，每表20,000行。
- 500条原业务连接，DRAIN前实测576,500条PS；`max_prepared_stmt_count=700000`
  是原runner按并发派生的容量，不是实际PS数量。
- 准备完毕后至少运行300秒，采集30个完整10秒业务区间。
  sysbench使用`--time=0 --events=0`；业务持续到DRAIN完成，原连接保持到receiver READY后才停止。
- source／receiver的Preserve预算各2GiB，buffer pool各2GiB，inflight上限1GiB。
  临时表、临时ID namespace和result capture均ON；source Phase1上限60秒，原6个pipeline worker。
- 保留EXACT BODY、strict≤2秒、末命令→Final ACK≤500毫秒、receiver同钟ACK→READY≤500毫秒，
  以及原连接／HOLD／READY／所有权与错误约束。

这一500并发结果单列，不替代原1000并发的容量验收。没有改为历史诊断中的4GiB预算、
60秒业务或600秒Phase1。receiver的Phase1配置仍是其600秒默认值，本轮不在receiver执行DRAIN。

本轮没有出现此前1000并发、2GiB预算下的receiver `RESOURCE_EXHAUSTED`。
receiver预算峰值仍低于2GiB。Preserve记账、RSS、原生PS内存和主机换页是不同口径，
不能相加或由其中一项判断内核对象总内存及换页影响。

提前sealed数399／398与final wire复用500的含义不同。后者不要求该wire此前已在receiver SEAL，
也允许capture_complete的快照在final编码后复用。不能用500减399／398推断尾部新捕获或完整重做量，
也不能把receiver查询候选数解释为已通过提前READY确认的数量。
receiver最终资源日志分别记录pending PS plans 90／108、failed_batches=0，最终全部READY；
该计划数没有与慢worker一一对应的计时证据。

## 尾部已定位的阶段

| 可见阶段ms | r01 | r02 |
|---|---:|---:|
| source target-worker墙钟 | **921.177** | **894.179** |
| early final candidate pass | 74.417 | 87.448 |
| transfer commit epoch | 49.319 | 44.061 |
| commit内层final metadata ACK | 12.811 | 11.423 |
| legacy transfer tail | 1046.131 | 1050.622 |
| PS final proof累计 | 6229.489 | 5707.510 |

两轮最大的可见耗时均在source target-worker阶段。该计时包含worker处理、并发staging及join，
范围见[源码](../../../sql/preserve_trx.cc#L22716)。PS final proof为10个并行worker的累计时间，
不能串行相加或直接等同墙钟尾部；final metadata ACK已包含在commit中，不能重复加。
各阶段计时器端点并非全部互斥，不将其相加所得差额称为精确未分类区间。

第二轮worker比第一轮少26.998ms，但EXACT尾部多68.857ms；legacy尾部只多4.491ms。
因此不能说worker变慢导致第二轮EXACT尾部上升，也不能把完整尾部称为网络ACK时间。
当前已定位主要阶段，仍缺慢worker关键路径与PS proof累计分项的对应证据，具体机制尚未闭环。
