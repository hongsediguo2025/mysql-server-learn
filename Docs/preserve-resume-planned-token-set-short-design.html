Preserve/Resume：Session-only 一次性连接集合设计

适用代码：MySQL 8.0.22 Preserve/Resume 当前工作树；范围：receiver 当前进程内最近一次成功 DRAIN handoff；源码状态同步：2026-08-18

Receiver 只维护一个 session-only 白名单 S。S 只包含“属于本轮 source session， 且在 DRAIN 最终边界已确认没有未提交事务”的 source connection ID。RESUME 命中后必须在专用锁下 原子 erase，确保一个 source connection ID 最多配对一个 target connection。

1. 最终语义

S = eligible_idle_session_ids
    + authoritatively_drained_no_transaction_ids

T = successfully_finalized_transaction_token_ids

S intersect T must be empty
Source session 的最终情况在 S 中RESUME 行为
DRAIN 分类时就是 eligible idle/no-trx 的普通 classic session是消费成员，确认无需绑定事务
Phase 2 命令边界为 eligible DRAINED_NO_TRANSACTION是消费成员，不绑定事务
事务成功转移否绑定当前 active epoch 的 promotion record
事务仍存在，但 source token-local 失败否无 record 时返回 handoff 专用错误
receiver 接收、导入或 prewarm 失败否无可绑定 record 时失败关闭
超时、结果未知或伪造 connection ID否不得降级为 session-only
集合缺失不能解释为 session-only。存在 active handoff 时，只有原子命中 S，或命中当前 epoch promotion record 的 ID 才能成功。其余 ID 一律失败，从而阻止代理误传/伪造 ID 获得无事务成功响应。

2. Source 形成集合

Preserve_batch_target_counter 已在持有 THD::LOCK_thd_data 时读取 idle、活动事务、在途 statement 和 closing 前 packet。统一谓词 preserve_trx_session_only_candidate_is_eligible_locked() 还要求： THD 存活、非 system、未 killed、classic protocol、逻辑 idle、没有 SESSION/STMT engine participant，并且 preserve_trx_is_unsupported_common_context() 为 false，并且不持有任何临时表。即便某类临时表可由事务 bundle/sidecar 保存，session-only ID 本身也没有这些 payload；持有 XA、LOCK TABLES、user lock、server cursor、临时表等服务端上下文时， 整轮 DRAIN fail-closed，不能把该 ID 静默放入 S。

这里的“逻辑 idle”不能只看 THD::m_server_idle。CLOSING 后 packet header 已到达、但命令字节尚未解码时， m_server_idle 已为 false，server 仍不知道它最终是应返回 4020 的普通命令，还是没有响应并将断开连接的 COM_QUIT。源码使用两个 THD-local atomic 字段表达这个三态窗口：

preserve_trx_post_closing_command_classified = false; // 尚未解码
preserve_trx_post_closing_cleanup_packet = false;

// get_command() 成功后，先发布 COM_QUIT 分类，再发布 classified=true。
preserve_trx_post_closing_cleanup_packet = (command == COM_QUIT);
preserve_trx_post_closing_command_classified = true;
最终扫描时的 command 状态候选处理理由
m_server_idle=true按其余 eligibility 保留已经处于稳定命令边界
CLOSING 后普通命令已经分类、等待 4020按其余 eligibility 保留命令不会执行，连接仍属于 source session
CLOSING 后 packet 尚未分类或读包失败最终集合排除无法证明它不是 COM_QUIT，必须 fail-closed
已经分类为 COM_QUIT排除，但不使整轮 DRAIN 失败连接已经不可逆地进入 teardown，即使 THD 尚存活
COM_STMT_CLOSE视为仍存活 session只释放 prepared statement，不关闭 THD/连接

初始 counter 可以把“CLOSING 后尚未分类”的既有连接 ID 暂时加入候选集，但仍校验事务、临时表和 unsupported context； 这是为了避免普通命令在极短解码窗口中被永久漏掉。该 provisional ID 只有在最终快照已经分类为普通命令，或重新回到 m_server_idle 时才能留下。初始扫描若已经看见 COM_QUIT，只忽略该连接，不设置 m_has_unsupported_transaction。

m_declared_tokens、m_finalized_tokens、m_aborted_tokens 继续只作为传输协议账本； 不改变其含义。Phase 2 最终提交前会遍历当前 THD，但只对已有候选集合做交集复核：仍存活且仍满足统一 eligibility 的 ID 被保留， 未分类 packet、已解码 COM_QUIT、被 killed 或已经失格的 ID 被删除；COM_STMT_CLOSE 不等价于断连。 该扫描绝不把 closing 后新建的连接加入 S。 control-only 与包含事务的两条 COMMIT 路径都使用同一复核函数，扫描完成点就是 S 的 source 端线性化边界。

3. COMMIT_EPOCH 与 Receiver 数据

S 以非零、升序、唯一的 vector 编入 COMMIT_EPOCH.manifest_payload，使用独立 magic PTRX_SSET_V1。12-byte magic、4-byte count 和每 ID 8 bytes 必须限制在 1 MiB，因此最多 131070 个 ID。 现有 authenticated transfer principal、payload digest、完整 frame digest、sequence 和 commit admission 共同保护它， 不增加逐 ID 签名或 durable fact。

// Process-local; no persistence and no history map.
mutable std::mutex m_session_only_mutex;
bool m_active_session_only_set_valid{false};
std::unordered_set<uint64_t> m_active_session_only_tokens;
std::string m_active_session_only_epoch_id;
uint64_t m_active_session_only_generation{0};

Source 与 receiver 都校验 S ∩ T = ∅。只有 COMMIT admission 成功后，receiver 才在 m_session_only_mutex 下整体 swap 新 set、epoch，并递增 generation。合法空 set 也必须覆盖旧 set。

// Only in-flight transaction RESUME claims; also process-local.
std::set<std::pair<uint64_t, uint64_t>> m_transaction_handoff_claims;

// Source freezes the complete encoded COMMIT, not a second copy of vector S.
bool m_final_metadata_accepted{false};
std::string m_frozen_commit_payload;
std::array<unsigned char, kPreservedTrxSha256Length>
    m_terminal_fact_digest{};

短 claim 的 key 是 (handoff_generation, connection_id)。它不保存事务，不形成历史 epoch map，只阻止旧、新 epoch 对同一个数值 connection ID 并发进入恢复。第一次 COMMIT 发送尝试前，source 把 canonical S、epoch、fence、trx-id-store proof 和 terminal digest 一次编码进 m_frozen_commit_payload。后续重试必须解码并核对同一 S，然后原样复用整帧， 防止 ACK 不确定时改写 terminal payload 的授权集合。

事务 epoch 同时保留两个摘要域：既有 fact_digest 只描述 finalized transaction manifests； terminal_fact_digest 使用独立 domain 把该基础摘要与 canonical S、epoch 和 durable fence proof 绑定。 Control-only COMMIT 没有 transaction fact，因此使用另一个独立 domain 直接绑定 epoch、fence proof 与 S。Receiver 在 Preserve_trx_transfer_accepted_epoch 中分别保存两者，terminal CAS、QUERY/ABANDON 和 fallback resolution 一律比较 S-bound terminal digest，不能跨摘要域比较。

若 final metadata 已全部确认、但 COMMIT ACK 不确定，m_final_metadata_accepted 使重试跳过 metadata，直接重发冻结的 COMMIT；否则不同 payload 会被 uncertain-connection 保护拒绝。若 metadata 本身 ACK 不确定，仍沿用 fail-closed 的 precommit uncertainty 处理。本设计没有增加新的 wire command，只修正既有 COMMIT/QUERY/ABANDON 重试状态。
Frame layout 仍是 product protocol v2，manifest_payload 是已有扩展槽位。新 source 的所有 COMMIT 都编码 S， 包括规范空集合；新 receiver 将旧 source 的无 payload transaction COMMIT 映射为“active + 空 S”，避免错误降级到本地 RESUME。 滚动升级必须 receiver-first；新 source 对旧 receiver 会被旧端拒绝并保留 source ownership，属于 fail-closed。

3.1 为什么不是多个 shard set

当前只需要一个专用 set 和一把专用锁。session-only 路径按固定顺序短暂持有既有 g_preserved_trx_mutex -> m_session_only_mutex，在同一线性化点完成“没有 transaction record”与 find/erase；事务路径只在 m_session_only_mutex 下登记/释放一个短 claim。权限检查、session 恢复、 InnoDB attach 和网络返回都不在 m_session_only_mutex 临界区内，因此 RESUME 主体不会被串行化。

不复用 receiver registry 的大 m_mutex，避免和 transfer/reaper/commit 状态竞争。现在做多 shard 会引入跨 shard 的 epoch 原子切换、锁序和旧 generation 清理，违反“最小正确实现”。只有压测证明这个短临界区成为瓶颈后才考虑固定分片。

3.2 Control-only COMMIT

当本轮没有 finalized transaction 时，仍需发布 S（包括空 S）以覆盖旧 handoff。沿用窄 control-only COMMIT 分支：只跳过 transaction fact 构造，继续携带 trx-id-store/fence proof，并使用 session_only_control_fact_digest()、frame sequence、admission 与 ACK。Receiver 只允许 token=0、空 transaction snapshot 且 canonical S payload 完整的 control-only COMMIT。

4. RESUME 原子消费

handoff = snapshot_active_handoff(canonical_source_connection_id);
record = preserved_trx_find_record(token);

if (!handoff.available) {
  return existing_local_preserve_resume_path();
}

if (handoff.session_only) {
  require(RESUME_ANY privilege);
  require(target has no active transaction or engine participant);
  status = consume_under_record_then_session_lock(handoff);
  if (status == RECORD_CONFLICT) {
    return ER_PRESERVE_TRX_INVALID_STATE;  // S is not consumed
  }
  if (status != CONSUMED) {
    return ER_PRESERVE_TRX_HANDOFF_UNAVAILABLE;
  }
  return OK;                              // S erased; no transaction attach
}

if (!record exists || !record.has_promotion_key ||
    record.promotion_key.epoch_id != handoff.epoch_id) {
  return ER_PRESERVE_TRX_HANDOFF_UNAVAILABLE;
}

claim_current_handoff_generation(handoff); // short, one ID at a time
return existing_promotion_record_resume_path(record);

Snapshot 返回当前 token 是否在 S、epoch 和 generation。真正授权在专用锁下发生。两个 target connections 并发使用同一个 source ID 时，最多一个线程 erase 成功；另一个线程看到成员已消失或 epoch/generation 改变并失败。 record 冲突检查与 erase 不再是两次可穿插的查询。事务路径在写 attach intent 前 claim 当前 handoff generation，旧 snapshot 在新 epoch 已发布后不能开始 attach；已先 claim 的恢复可继续，但同一数值 ID 在 claim 释放前不能由新 epoch 再次消费。 事务路径仍由既有 record claim/take 保证单所有者，并保留“原 owner 或 RESUME_ANY”鉴权；只有没有 record 元数据可核验的 session-only 路径强制要求 RESUME_ANY_PRESERVED_TRANSACTION。

S 只负责 connection ID 授权和“一次配对”。它不包含 session payload，也不调用 restore_preserved_session_variables()。代理必须先通过既有链路完成认证和 session context 反序列化，再调用 RESUME； 本补丁成功返回只表示该 source ID 属于本轮 handoff 且无需 attach transaction。
一次性消费不是 SQL 级幂等接口。若 server 已消费 ID 并执行 my_ok()，但代理未收到 OK，盲目重试会失败。 代理必须保留成功返回的 target socket，并禁止同一 source ID 并发配对。ACK 丢失若需要可重试语义，必须另行引入 request nonce 或查询接口；本次实现不增加该复杂度。

6. 状态机

NO_ACTIVE_HANDOFF
  -- accepted COMMIT_EPOCH(S, epoch) --> ACTIVE(epoch, generation, S)

ACTIVE(epoch, generation, S)
  -- accepted newer COMMIT ----------> ACTIVE(new_epoch, generation + 1, new_S)
  -- RESUME(id in S), erase succeeds -> ACTIVE(epoch, generation, S - {id}) + OK
  -- RESUME(id absent), no current record
                                     -> unchanged + HANDOFF_UNAVAILABLE
  -- RESUME(current promotion record) -> handoff claim -> record claim/attach
  -- RESUME(stale handoff generation) -> unchanged + HANDOFF_UNAVAILABLE
  -- receiver restart ---------------> NO_ACTIVE_HANDOFF

成员消费不改变 generation；generation 只标识一次完整 set 替换。Receiver 只保存最近一轮 handoff，新成功 epoch 覆盖旧 epoch。

8. 不变量与必测场景

  1. 只有通过统一 eligibility 的 idle/no-trx、provisional post-CLOSING packet 或权威 DRAINED_NO_TRANSACTION 才成为候选；最终复核只删除，不新增。
  2. provisional packet 在最终快照前必须已经分类为普通命令或回到 idle；未分类/read-error 一律不能进入 S。
  3. COM_QUIT 一经分类即排除且不能使整轮 DRAIN 失败；COM_STMT_CLOSE 仍代表存活 session。
  4. source/receiver failure、ABORT、artifact 缺失、timeout 和未知状态均不得进入 S。
  5. S ∩ T = ∅；双端校验冲突并 fail-closed。
  6. 第一次 session-only RESUME 成功且不 attach；第二次及并发竞争者返回专用错误。
  7. Phase 2 COMMIT 后 DNT 的 ID 进入 S，已发送 staging 按既有流程清理。
  8. 成功事务不在 S，只能通过当前 epoch record 恢复一次。
  9. source/receiver 失败 ID、随机数字 ID、旧 epoch ID 均不能 session-only 成功。
  10. record 与 session-only ID 冲突时返回 INVALID_STATE，不消费成员。
  11. target 已有活动事务或 engine participant 时返回 INVALID_STATE，不消费成员。
  12. 旧 snapshot 遇到新 epoch 覆盖时 consume 失败，不删除新 set 中的同值成员。
  13. 事务 RESUME 必须 claim 当前 handoff generation；同一个数值 ID 不能跨 epoch 并发恢复。
  14. 第一次 COMMIT 发送尝试后，同一 source epoch 不能改用另一份 S。
  15. 事务 terminal digest 必须绑定基础 transaction fact 与 S；control-only 使用独立摘要 domain；fallback 不得比较错误摘要域。
  16. final metadata 已确认后的 COMMIT 重试不得重发 metadata，且必须逐字节复用冻结 COMMIT。
  17. 连续 epoch（包括空 set）整体覆盖；失败 COMMIT 不修改旧 active handoff。
  18. receiver 重启后集合消失；本设计不承诺跨重启 session-only RESUME。
